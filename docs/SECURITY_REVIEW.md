# مراجعة الأمن والتشغيل — M12

| فصل الأنواع والأدوار وعزل الموارد | تفحص حراسة `auth/access.ts` جمهور JWT للمسارات الثلاثة وتفحص الأدوار على الخادم. تستخدم الاستعلامات معرّفات العميل والمطعم من الهوية المصادق عليها، وتعيد `404` عند طلب مورد غير مملوك لصاحبه. الأدلة في `tokens.test.ts` و`customer-addresses.test.ts` و`order-read.test.ts` و`order-transition.test.ts` و`admin-console.test.ts`.                |

## إعداد الإنتاج الذي يؤثر في التحقق

- خلف وسيط عكسي محلي، يحتاج تحديد المعدل وسجل التدقيق إلى عنوان العميل كما يراه الوسيط. أضيفت ثقة اختيارية باتصالات loopback فقط، وتقبل لوحة الإدارة قيمة IP واحدة عند تفعيلها. يختبر `auth-infrastructure.test.ts` أن عميلين خلف الوسيط يحصلان على حدود منفصلة، ويختبر `apps/admin/lib/backend.test.ts` تفعيل تمرير العنوان وصيغته. يوثّق دليل التشغيل إعداد الرؤوس وربط العمليتين محلياً. [إعداد ثقة Fastify بالوسيط](https://fastify.dev/docs/latest/Reference/Server/#trustproxy)
- نوافذ تحديد معدل الدخول والتصفح وإنشاء الطلب في ذاكرة عملية API واحدة. يعمل حد OTP في قاعدة البيانات. يتوافق التحقق مع نشر عملية API واحدة على الخادم، كما تصف بنية MVP.
- يعالج معالج الأخطاء أيضاً رفض معلمات المسار أثناء التوجيه قبل استدعاء المعالج. يتحقق `auth-infrastructure.test.ts` من الرد العربي عند رفض معلمة أطول من الحد. [أخطاء إطار Fastify](https://fastify.dev/docs/latest/Reference/Server/#frameworkerrors)
- تشغيل OTP في الإنتاج وتجربة الوصول من داخل سوريا واختيار طريقة توزيع Android ضمن [بوابات التحقق الخارجية](OPEN_QUESTIONS.md). اختُبر عقد التخزين المحلي. يتطلب اختبار عقد S3 تعريف `S3_ENDPOINT`.
